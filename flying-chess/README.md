# 飞行棋 · Flying Chess（网页版）

经典四人飞行棋，纯前端单文件、零依赖、零外部素材，支持 **1-2 名真人在同一页面轮流操作**，其余座位由电脑玩家（AI）自动接管。

## 怎么跑

- 直接双击 `index.html` 即可（file:// 可用，无需服务器）；
- 或在本仓库根目录起静态服务：`python -m http.server 5173`，访问 `http://localhost:5173/flying-chess/`。

## 玩法与规则

| 规则 | 说明 |
|------|------|
| 起飞 | 投出 **6** 才能把飞机从机库移到起飞点；投 6 获得**再掷一次** |
| 连掷三个 6 | 本次作废直接交棒（经典惩罚） |
| 行进 | 顺时针绕 56 格主航道一整圈，第二次经过本臂臂尖时转入 5 格**终点航道**直抵中心 |
| 同色飞跃 | 正好落在本色 ★ 跳点（起飞后第 4 / 8 格）额外前进 4 格，不连锁触发 |
| 撞击 | 落在对手所在的**主航道**格 → 对手机被击回机库，己方获得一次重掷；终点航道内安全 |
| 到达中心 | 需**精确点数**，超出部分沿原路反弹后退 |
| 胜利 | 4 架飞机全部抵达中心即获胜，本局结束并显示名次 |

操作：真人回合点击**己方机库中央的骰子**（或空格键）掷骰——轮到哪方，骰子就显示在哪方机库里，脉冲光圈表示可点击；若有多架可动飞机，点击棋盘上闪烁高亮的飞机选择要动的。全部可动选项都是「起飞」时自动执行，无需选择。

## 界面布局

- **棋盘内嵌 UI**：玩家信息（阵营名、真人/电脑徽章、已抵达 ✈ n/4）直接绘制在四角机库区内，当前行动方机库带呼吸高亮；骰子同样画在机库中央（Canvas `drawDie`），随回合切换位置，无侧栏 DOM 骰子/按钮；
- 侧栏只保留一张「战况」卡片：顶部是当前回合提示语，虚线分隔下是滚动对局日志；小屏（≤860px）下该卡片占满整行宽度；
- 机库几何：`hangarRect(c)` 给出框矩形（左上/右上/左下覆盖格 0..5，右下覆盖 9..14），`HANGARS` 四角机位与 `HANGAR_CTR` 骰子中心均严格对称于框中心，点击框内任意处即可掷骰。

## 棋盘几何（15×15 网格）

- 主航道 56 格闭环：4 条臂 × 13 格 + 4 个转角格，**臂尖格属于主航道**（对应真实飞行棋"绕一圈后从臂尖跳入中超"）；
- 每条臂的中列 5 格是该臂颜色的终点航道，中央 3×3 为四色三角终点区；
- 四色起飞点间隔 14 格（红 0 / 黄 14 / 蓝 28 / 绿 42），完全旋转对称；
- 每架飞机的位置用一个相对步数 `r` 表达：`-1` 机库、`0..62` 主航道、`63..67` 终点航道、`68` 中心，所有规则（撞击/入超/反弹/飞跃）都在这个一维模型上计算，再映射回格子坐标绘制。

## AI 策略

启发式打分选走法：撞击对手 > 抵达中心 > 起飞（机库剩机多时优先）> 逃离威胁（被对手 1~6 步射程覆盖）> 转入终点航道 > 推进进度，附微小随机避免完全 deterministic。

## 代码结构（index.html 内单脚本）

1. `COLORS / RING / LANES / HANGARS / HANGAR_CTR / hangarRect`：棋盘几何常量表；
2. `landR / capturesAt / legalFor / dangerIdx`：走法与规则计算（纯函数，可无头测试）；
3. `aiPick`：电脑走法选择；
4. `drawBoard / drawPieces / drawDie`：Canvas 绘制（每帧重绘，选中飞机与可掷骰子脉动动画）；
5. `startRoll / doMove / nextTurn / gameOver`：回合流程状态机，`token` 变量用于重开局时终止旧的异步动画链。

## 回归测试

`node _test.js`：桩掉 DOM/Canvas，先做棋盘几何自检（闭环相邻、航道不重叠、臂尖入超相邻），再让 4 个 AI 全自动对局直到分出胜负，校验胜利判定与位置合法性。

## 已知简化（相对实体飞行棋）

- 未实现：迭机（同色叠坐）、对家超级跳、6 起飞直跳 6 格等地方规则；
- 同色飞机可共存于同一格，不合并移动；
- 撞击结算以掷骰瞬间的落点快照为准。
