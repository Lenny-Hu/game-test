# 菇侠冒险 · Super Shroom Run

经典玩法的横版动作平台跳跃网页版，单文件纯 Canvas 2D，零依赖、零外部素材。
橙发菇侠从「晨光草原」一路跑到「终局魔城」，顶砖、吃菇、吐火球、踩栗子、踢龟壳；
九关逐关解锁、长度从 224 列递增到 608 列，关卡中途有**检查点**，但命只有 2~5 条——时间归零或跌落深坑都会带走一条。

> 名称、主角美术、敌人造型与音效均为**原创程序化绘制/实时合成**，仅玩法致敬横版跳跃品类（机制不受版权保护）。
> 未使用任何任天堂相关名称、角色、图形或音频。若将来上架小游戏平台，仍需进一步差异化名称与美术（避免他人注册商标与角色形象）。

## 规则速览

| 项目 | 值 |
|---|---|
| 舞台 | 瓦片 36px × 16 行，地面顶边第 14 行，设计视口 1008×576，仅横向卷轴镜头 |
| 形态 | 小只 →（吃菇）大只 →（吃花）火只；大只受击降为小只，火只受击降为大只，小只受击即死 |
| 无敌 | 星星 6~10 秒（随难度），碰到敌人直接击杀且自身不受伤害 |
| 关卡 | 9 关（晨光草原 / 蜜糖峡谷 / 云顶砖城 / 翠雾密林 / 齿轮工厂 / 熔岩洞窟 / 星夜高塔 / 落霞砂糖 / 终局魔城），逐关解锁，通关即解锁下一关 |
| 检查点 | 每关 1 个：从关卡中点向两侧找「脚下实心 + 身位净空 + 前后 15 格无坑 + 13 格内无敌人」的列，过了就在那儿复活 |
| 补给 | 后六关的路面上直接摆蘑菇与火花（`m` / `f` 瓦片在建模时转成贴地道具），跑过去就能吃，是长关卡的续航来源 |
| 时限 | 300~420 秒 × 难度时限倍率，归零直接判定死亡 |
| 结算 | 触杆奖励 = (杆底行 − 触杆行) × 300 + 剩余时间 × 50，整段再按难度得分倍率放大 |
| 最高分 | 按 难度 × 关卡 二十七格存 localStorage（`shroom_best` / `shroom_diff` / `shroom_unlock`） |

后六关各配一套天空 + 地面/草木/水管主题色（`SKYCOL` / `SKYTHEME` 九套），前三关沿用入库原色，改关卡不影响旧观感。

关卡由 16×16 的**块模板**拼接（`LEVELS[i].parts` 是块名序列），28 块为：
`start` `flat` `qrow` `brickbox` `highbrick` `power!` `starbox` `supply` `coinsky`
`pit2` `pit3` `pitwide` `pitkoopa` `ledge` `gapledge` `stairsU` `stairsD`
`pipe2` `pipe3` `twinpipe` `enemies2` `koopa` `hopper` `hopgauntlet` `shelltrap` `fort` `flagend` `castleend`。
难度只改参数（速度/时限/生命/倍率）不改几何，因此同一关在三档难度下的地图完全一致、纪录分列二十七格。

## 物理常量（px、秒）

| 常量 | 值 | 含义 |
|---|---|---|
| GRAV | 2050 | 重力 |
| JUMP_V | 790 | 起跳初速（满跳升高 ≈152px ≈ 4.2 格） |
| JUMP_CUT | 170 | 松手上升截断（点按小跳） |
| COYOTE / JBUF | 0.09 / 0.11 | 土狼时间 / 跳跃缓冲 |
| ACC / AIR_ACC | 1500 / 1150 | 地面 / 空中加速度 |
| FRICTION | 1700 | 地面松手减速 |
| WALK_MAX / RUN_MAX | 300 / 430 | 走 / 跑极速 |
| MAX_FALL | 980 | 下落限速 |
| STOMP_BOUNCE | 430 | 踩怪反弹 |

满速跑跳滞空 ≈0.77s、水平触及 ≈331px，故坑宽上限 5 格（180px）。
碰撞为**轴分离的扫掠 AABB**：位移按 ≤10px 拆子步后逐段判定，因此高速不穿透薄墙；顶头命中会回写「最靠近角色中线的那一块」。

## 敌人 · 道具 · 分值

| 敌人 | 体型 | 速度 | 分值 | 特性 |
|---|---|---|---|---|
| 蓬蓬栗 g | 28×26 | 62 | 100 | 直行碰壁转向，可踩 |
| 团团龟 k | 28×34 | 54 | 200 | 踩一下变龟壳，再踩/推即滑行，撞到的敌人立毙 |
| 蹦蹦蝠 h | 30×28 | 40 | 150 | 周期性跳跃（起跳时机由种子决定），也可踩成壳 |

- 龟壳：踢出 +150，滑行 470px/s，撞到的敌人立毙（该敌分值 ×2），静止 5s 后原主复活；连击倍率 `[1,2,4,8,8]`（落地前连续踩怪递增）。
- 火球：同屏最多 2 发，520px/s 抛出并弹地，命中敌人致死（该敌分值 ×1）。
- 道具：蘑菇（变大，+1000）、火花（变火，+1500）、星星（无敌 6~10s，+1500）、金币 +100、碎砖 +10、问号出币 +200。
- 路面道具：`m` = 蘑菇、`f` = 火花，直接贴在地板上（不靠顶砖弹出，火花不自行移动），`buildLevel` 建模时把该瓦片清空并生成道具实体。后六关各摆 1~5 个 `supply` 块（每块 1 菇 + 1 花），保证跑动中一定能吃到补给。
- 复活保护：`respawn()` 给 1.1 秒无敌（`SPAWN_GRACE`），配合「检查点附近不留敌人」，避免出生瞬间被身后的巡逻怪收命形成无法挣脱的重复死亡。
- 上表分值一律再乘难度得分倍率（`score()` 统一放大）；每 100 金币 1 UP。

## 操作

- **键盘**：`← →` / `A D` 移动，`空格` `↑` `W` `Z` `K` 跳跃，`Shift` `B` 冲刺，`X` `J` 火球。
- **快捷键**：`Enter` 确认（开始/下一关/重开），`Esc` 暂停或返回，`M` 静音，菜单里 `1/2/3` 选难度。
- **手机竖屏**：场景带下方绘虚拟键（左/右/跳/冲/火），支持多点触控边跑边跳；首次触屏自动弹出，接回键盘自动收起。
- **HUD**（画在场景内的顶栏，非 DOM）：分数 / 金币 / 世界（关卡名 + 检查点 `A|B`）/ 时间（末 30 秒闪红并滴答）/ 生命，右侧三个圆形按钮 `菜单` `音|静` `1x|2x|3x`（倍速为每帧多跑几个固定子步，不改变判定顺序）。
- 面板（主菜单含难度×关卡二十七格纪录表 / 选关 3×3 九卡 / 暂停 / 单关结算 / 失败 / 全通关 3×3 得分卡）与 HUD、虚拟键全部画在 Canvas 场景内，命中区注册进 `G.ui`，无 DOM 弹窗。

## 确定性

- 逻辑固定步长 `STEP = 1/60`，倍速只是每帧多跑几个子步。
- 一切影响玩法的随机都走种子 LCG：`setSeed(20260927 + 关卡序号 × 7919)`（装饰相位、敌人起跳时机）；粒子才用 `Math.random`。
- 因此「同一份输入脚本 → 逐位一致的状态」，回归测试靠这一点做整局重放。

## 回归测试

```bash
node _test.js          # 约 0.9s，全绿输出「全部断言通过：10111 项」
```

12 组断言覆盖：常量与数据表、28 个关卡块审计、拼接几何审计（水管不悬空且高度 ≤4 格、可顶块上方留净空、
逐段坑宽 ≤5 格且两坑之间落脚岛 ≥8 格、检查点列 15 格窗口内无坑、复活点 13 格内无敌人、路面道具贴地且下方实心）、
瓦片扫掠碰撞（含顶墙 600 帧不得积累超速）、顶砖/问号/道具/形态切换、踩杀与龟壳（连锁必须由滑行的壳自己撞到目标，测试不再手工调用 `killEnemy` 凑断言）、
火球与无敌、死亡/生命/检查点/复活保护窗口/时限/结算、同输入确定性重放、面板内按钮注册与点击流（含场景内命中区两两不得遮挡、选关 3×3 九格位置互不重复、竖屏虚拟键不重叠不越界）、
localStorage 二十七格纪录、输入驱动 Bot 整局必胜与「原地不动必败」（不操作时每条命都耗到时间归零，最终 over）、pointer 通道与倍速。

Bot 只用真实输入位（`IN.left/right/jump/run/fire`）驱动游戏，三档难度 × 九关 **27/27 必胜**（用时 / 过关时剩余生命）：

| 难度 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| 休闲 | 19.5s·5 | 23.4s·5 | 30.0s·5 | 42.1s·4 | 38.0s·5 | 41.6s·5 | 44.1s·6 | 50.8s·5 | 53.5s·5 |
| 标准 | 27.3s·2 | 23.4s·3 | 29.9s·3 | 53.2s·0 | 37.8s·3 | 51.1s·2 | 56.5s·3 | 54.5s·2 | 70.6s·2 |
| 挑战 | 19.4s·2 | 26.8s·1 | 53.0s·0 | 35.1s·2 | 37.7s·2 | 63.5s·0 | 58.2s·2 | 50.7s·2 | 69.9s·1 |

九关累计得分实测 easy 263710 / normal 319920 / hard 440600，测试把 250000 / 300000 / 420000 记为下界；
休闲第 7 关「剩 6 命」多于初始 5 命，是途中吃满 100 金币拿了 1 UP。
摆了 `supply` 的关卡（第 4~9 关 × 三档 = 18 档）还断言 Bot 的火焰形态帧占比 > 10%，防止路面道具白放；
前三关不含 `supply`，且断言 `fireF === 0`（Bot 全程小形态硬吃，保持入库时的挑战曲线）。

Bot 判跳用抛物线预测：探测坑沿与远端落点、正前方台阶、同层最近敌，
`arcH(x) = JUMP_V·t − ½·GRAV·t²`（`t = (x−x₀)/vx`）配合滞空触及 `reach` 决定「跳得过且落得开」才起跳；
贴脸（<60px）或坑沿（<24px）则无条件起跳。两条硬约束记在测试与实现里：**落地帧必须重置按压**、**按下必须来自新的抬升沿**——
否则长按不松手时游戏再也收不到跳跃指令，Bot 会在墙根卡死（这是历史上最难查的一次卡关）。

**调平记录（本轮扩到九关时踩的坑）**：敌人密度翻倍后，仅靠「关卡不变长」是过不了的——Bot 常态是小形态，
任何一次接触即死，而每 16 列的敌人块平均要带走 0.3~0.7 条命，hard 只有 2 条命。
解法不是砍 Bot 也不是砍怪，而是补上三条系统性缺口：路面补给（拿到火球后远程清怪 + 多一条命）、
检查点避开坑与巡逻怪、复活 1.1s 保护窗口。改完 27 档全绿，且关卡长度与敌人密度仍按原设计递增。
